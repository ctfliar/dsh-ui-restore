# 知识库

面向「用 dsh-ui-restore + Paper 做视觉还原/设计」的可复用经验。**按项目平行组织**，一个项目一个目录，跨项目复用的方法/配方放 `patterns/`。

## 结构

```text
docs/knowledge/
├── README.md                     # 本文件：索引与约定
├── projects/
│   └── <project-slug>/           # 一个项目一个目录（可平行多个）
│       ├── README.md             # 项目简报、输入清单、设计系统、案例索引
│       ├── cases/                # 案例：YYYY-MM-DD-<topic>-<status>.md
│       └── assets/               # 本项目证据/成图（不含品牌素材）
└── patterns/                     # 跨项目复用：提示词配方、style tokens、模板
```

## Agent 接线说明

五个 Agent 预设（队长 / 设计师 / 画师 / 验收者 / 接线者）的 SKILL 与 persona 都声明了
「开工先查项目知识库」。Agent 是**按需读取**：只读与当前任务相关的项目 README、最近案例和
`patterns/` 配方，**不自动加载整库**，也不把知识库当设计源。

| 角色 | 读什么 | 用到哪一步 |
| --- | --- | --- |
| 队长（ui-restore） | 项目 README、案例索引、最近 failed 案例 | 开工定模式；派活时在交接里带「参考案例」路径 |
| 设计师（ui-restore-designer） | `patterns/` 配方与模板、失败案例、项目设计系统 | 出设计包前定风格与刻度；生成后做风格自检 |
| 画师（ui-restore-painter） | 项目设计系统、图块/风格模板 | 实现前对齐色板、尺寸与标签规格 |
| 验收者（ui-restore-verifier） | 项目设计系统、失败案例、双层验收清单 | 判定时结构层 + 风格层分别取证，并指到具体项 |
| 接线者（ui-restore-integrator） | 项目 README 的 api 约定、相关案例 | 接口接线前确认口径与状态处理 |

边界：别的项目的案例只能借方法、不能借数值；失败案例只作教训，不做基准；案例不足时按通用流程做，
做完再补案例，不为凑案例停工。

## 约定

- **项目目录**：`projects/<slug>/README.md` 必须写清项目简报、输入清单（参考图/链接/名单，敏感素材只写来源不复制）、设计系统、案例索引。
- **案例命名**：`YYYY-MM-DD-<topic>-<status>.md`；`status` ∈ `passed` / `failed` / `superseded`。
- **失败案例必写**：期望、实际、证据截图、根因、教训、后续如何被修正。失败版本同样入库，不删。
- **资产**：只放产出与证据；命名 `<版本>-<描述>.<ext>`（如 `v1-gen-page1.jpg`）。品牌商品图、客户设计稿不入库，只写来源路径。
- **跨项目复用**：提示词配方、风格 token、模板、检查清单放 `patterns/`，项目 README 引用，不复制粘贴。
- **新增项目**：建目录与 README → 放案例与资产 → 更新本索引。

## 通用方法

1. **模态先行**：需要「看图」的任务，先确认模型路由声明了 `image`（DSH 的 `inputModalities`），否则风格判断无依据。
2. **风格提取要取全**：底色、圆角、阴影、标签字号、商品占比，与「画了什么」同等重要；只看透明物件会漏掉底卡。
3. **生成与排版分离**：生成模型只负责商品与底；文字标签用 HTML/SVG 叠加。
4. **负向约束**：无底座、无棚拍地板、无背景板、无文字、edge-to-edge 纯色底，比正向描述更有效。
5. **生成必须目检**：结构指标（对齐/裁切/溢出）≠ 风格达标；每页截图逐张看。
6. **单张重生成**：只重跑不合格的品类，不整页重来，省额度。
7. **验收分两层**：结构层（几何/对齐/裁切）+ 风格层（对照参考图：底、占比、材质、标签）。
8. **版本隔离**：旧画板删除或归档，失败版本截图进知识库，不留在最终画布里。

## 品类名 → 图标的推导规则

当用户**只给品类名**（不给商品清单、不给底色）时，设计师按 `patterns/prompts.json` 的 `derivation` 自行推导，**不要反问**：

1. **商品**：2–3 个代表性具体物件（可辨识、非品牌、可 3D 渲染），避免抽象符号；
2. **底色**：按品类色族映射（食品/粮油/生鲜 → 暖色；家清/个护/母婴/护理 → 浅蓝；数码/汽车/企业办公 → 中性；
   运动/生活电器 → 浅绿；箱包/服饰 → tan/cream；美妆 → 粉；节日 → 浅红；工业劳保 → 浅黄）；
3. **兜底**：新品类没有直接映射时，从已采样色板选最接近的色族，理由写进 assumptions，不得新增品牌色/高饱和。

验收者风格层额外查两项：**品类可辨识性**（商品是否对应品类）与**色板合规**；推断不合理判 `needs_revision`。

## 风格分怎么用（风格指标）

- 来源：`ui_diff` 的 `style` 字段与 `ui_report` 的「风格指标」段（色板距离、明度/饱和、边缘密度、填充率）；
- 读法：≥0.95 接近；0.90–0.95 小差异；0.80–0.90 明显差异；<0.80 回归明显；
- 实测基线（本项目）：v2 自比 1.00，v1 vs v2 0.79，v0 vs v2 0.60，灰度化 0.70，**同版本跨页约 0.85**；
- 注意：分数包含商品内容色，同风格不同品类约 0.85，**不是 pass/fail 判据**；只作风格层证据与回归基线，判定仍看结构层 + 人/视觉复核。
