# 知识库

面向「用 dsh-ui-restore + Paper 做视觉还原/设计」的可复用经验。**按项目平行组织**，一个项目一个目录，跨项目复用的方法/配方放 `patterns/`。

## 结构

```text
docs/knowledge/
├── README.md                     # 本文件：索引与约定
├── projects/
│   └── <project-slug>/           # 一个项目一个目录（可平行多个）
│       ├── README.md             # 项目简报、输入清单、设计系统、案例索引
│       ├── cases/                # 案例：YYYY-MM-DD-<topic>-<status>.md
│       └── assets/               # 本项目证据/成图（不含品牌素材）
└── patterns/                     # 跨项目复用：提示词配方、style tokens、模板
```

## 约定

- **项目目录**：`projects/<slug>/README.md` 必须写清项目简报、输入清单（参考图/链接/名单，敏感素材只写来源不复制）、设计系统、案例索引。
- **案例命名**：`YYYY-MM-DD-<topic>-<status>.md`；`status` ∈ `passed` / `failed` / `superseded`。
- **失败案例必写**：期望、实际、证据截图、根因、教训、后续如何被修正。失败版本同样入库，不删。
- **资产**：只放产出与证据；命名 `<版本>-<描述>.<ext>`（如 `v1-gen-page1.jpg`）。品牌商品图、客户设计稿不入库，只写来源路径。
- **跨项目复用**：提示词配方、风格 token、模板、检查清单放 `patterns/`，项目 README 引用，不复制粘贴。
- **新增项目**：建目录与 README → 放案例与资产 → 更新本索引。

## 通用方法

1. **模态先行**：需要「看图」的任务，先确认模型路由声明了 `image`（DSH 的 `inputModalities`），否则风格判断无依据。
2. **风格提取要取全**：底色、圆角、阴影、标签字号、商品占比，与「画了什么」同等重要；只看透明物件会漏掉底卡。
3. **生成与排版分离**：生成模型只负责商品与底；文字标签用 HTML/SVG 叠加。
4. **负向约束**：无底座、无棚拍地板、无背景板、无文字、edge-to-edge 纯色底，比正向描述更有效。
5. **生成必须目检**：结构指标（对齐/裁切/溢出）≠ 风格达标；每页截图逐张看。
6. **单张重生成**：只重跑不合格的品类，不整页重来，省额度。
7. **验收分两层**：结构层（几何/对齐/裁切）+ 风格层（对照参考图：底、占比、材质、标签）。
8. **版本隔离**：旧画板删除或归档，失败版本截图进知识库，不留在最终画布里。
